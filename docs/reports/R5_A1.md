# Batch A1 — Z1 Modbus client

NOT RUN — owner will verify.

- Root cause: the client used a callback transport, exposed a forgeable boolean write gate, and had no RTU/TCP links.
- Added abstract byte transport plus RTU, TCP, and simulator loopback links; framing, partial reads, RTU idle gap, CRC, MBAP transactions, timeout, and exception responses are handled.
- Client now requires a guard and link, selects permitted holding/input reads, validates PDU limits, byte counts, addresses, and write acknowledgements; removed delayed no-transport behavior.
- Write authorization has a private constructor, is minted only by `VerifiedWritePipeline` after session, confirmation, audit, identity, link, and safety checks, and is single-use/expiry/value-bound.
- Removed the prior boolean parameter throughout Modbus call sites and updated the prior guard/client tests without relaxing their assertions.
- Added `test/r5_modbus_client_test.dart` coverage for simulated RTU/TCP reads, guard blocking, missing/reused authorization, timeout, exception, malformed byte count, oversized PDU, and RTU address zero.
- Grepped all `ModbusClient`, guard, link, and authorization callers/implementers in `lib/` and `test/`; no `pipelineAuthorized` references remain.
- Uncertain: byte-level transports are intentionally abstract; no physical socket/serial integration or build/tests were run.
